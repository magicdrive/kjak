# kjak v1.1.0

kjak sends one notification to your desktop, Slack, Discord, e-mail, any
HTTP API or a plugin of your own, from the command line, a script or CI.
v1.1.0 adds notifications of the operating system kjak runs on, a tutorial
for every feather, complete configuration examples and a self-documenting
`kjak config init`. It is a minor release: everything v1.0.0 guarantees
([docs/stability.md](https://github.com/magicdrive/kjak/blob/v1.1.0/docs/stability.md))
is kept.

## Highlights

- **OS notifications: `type = "os"`.** A notification on this machine's
  screen, with no account and no secret:

  ```sh
  kjak feather add desktop --type os
  kjak send --to desktop --title "Build complete" --level success "All tests passed"
  ```

  macOS (amd64, arm64) through `/usr/bin/osascript` in a GUI session,
  Windows (amd64) through Windows PowerShell 5.1 and the WinRT toast API,
  Linux through `notify-send` with a D-Bus session. kjak installs and
  registers nothing; the text is passed as data, never as script
  ([docs/os.md](https://github.com/magicdrive/kjak/blob/v1.1.0/docs/os.md),
  [design](https://github.com/magicdrive/kjak/blob/v1.1.0/docs/design/os-notifications.md)).
- **Tutorials for every feather**, in English and Japanese: OS
  notifications, Discord, Slack, Gmail, any SMTP server, HTTP APIs and
  plugins, from the setup on the service to a first notification, with
  complete `config.toml` files
  ([docs/tutorials](https://github.com/magicdrive/kjak/blob/v1.1.0/docs/tutorials/README.md)).
- **Configuration examples**: complete files for one feather, several,
  groups, templates and secrets files
  ([docs/examples](https://github.com/magicdrive/kjak/blob/v1.1.0/docs/examples/README.md)).
- **`kjak config init` writes a catalog**: the same configuration as before
  (no feather), followed by a commented example of every feather, group,
  template and default, each linked to its tutorial. `kjak config init
  --minimal` writes it without the examples.
- **Comments kept when adding.** `feather add`, `group set` and `template
  set` of a new name now append to the file and keep its comments and
  layout. Other changes still rewrite it, and now say so when that drops
  comments (`kjak: note: FILE was rewritten without its comments`).
- **Documentation tested as code.** CI parses and validates every example
  and every TOML block of the tutorials and guides, runs every `kjak`
  command line they show against the real command line, checks every link,
  and fails when a feather type has no tutorial.

## Compatibility

- New: feather type `os`; delivery error codes `unsupported` and
  `unavailable` (an `os` feather only); flag `kjak config init --minimal`.
  These are additions allowed in a minor release.
- `os` is no longer a reserved type name. `native`, `macos`, `linux` and
  `windows` remain refused, now with a message naming `type = "os"`.
- `kjak config init` writes a longer file; its configuration is the same as
  v1.0.0's (tested). The text of the file is not part of the contract.
- `kjak feather types` lists `os` and no longer prints "Not supported yet".

## OS notifications: what `delivered` means

An `os` feather is `delivered` (acceptance `confirmed`) when the OS program
accepted the notification, not when someone saw it: Focus or Do Not
Disturb, the notification settings, or a locked screen can keep it off the
screen. Over SSH, in a service or in CI there is no screen: kjak reports
`unavailable` instead. On Windows, notifications turned off for Windows
PowerShell are reported as `rejected`. An `os` feather is never retried.

## Install

```sh
brew install magicdrive/tap/kjak            # macOS, Linux; brew upgrade kjak later
```

or, without Homebrew, on macOS and Linux:

```sh
curl -fsSLO https://raw.githubusercontent.com/magicdrive/kjak/v1.1.0/install.sh
sh install.sh --version v1.1.0              # into ~/.local/bin; sh install.sh --upgrade later
```

or the archive of your platform below, checked with `kjak_checksums.txt`
and, optionally, its build provenance:

```sh
gh attestation verify kjak_1.1.0_linux_amd64.tar.gz --repo magicdrive/kjak \
  --signer-workflow magicdrive/kjak/.github/workflows/release.yml --source-ref refs/tags/v1.1.0
```

Developers can build from source with Go 1.27 (`make build`, or
`go install github.com/magicdrive/kjak@v1.1.0`).

## Platforms

| platform | archive | OS notifications |
|---|---|---|
| macOS arm64, amd64 | `tar.gz`; Homebrew, install script | `osascript`, in a GUI session; shown as from Script Editor |
| Linux amd64, arm64 | `tar.gz`; Homebrew, install script | `notify-send`, with a D-Bus session |
| Windows amd64 | `zip` | Windows PowerShell 5.1 (WinRT toast), in a desktop session; shown as from Windows PowerShell |

## Known limitations

- An OS notification is shown under the identity of the OS program kjak
  uses (Script Editor on macOS, Windows PowerShell on Windows), not as
  "kjak"; it has no sound, icon or action. macOS and Linux do not tell kjak
  whether notifications are allowed or shown.
- CI checks that each OS accepts the notification script; whether it
  appears on a screen is checked by hand before a release.
- Windows has no keychain support. On macOS and Linux the keychain tools
  are tested as test doubles.
- Changes other than adding a feather, group or template rewrite the
  configuration file without its comments.
- Plugins are not sandboxed: they run with your rights.
- The macOS binaries are not notarized.
